## Reproduce

The snapshot pins Lean 4.35.0 and Mathlib commit 56a005855ea17e0b0958f73ec801ae140b0a1679. With Lean installed:

```sh
cd quartics/quartic-318-326/proof/progress
python3 verify_manifest.py
lake exe cache get
bash replay.sh
```

`replay.sh` kernel-checks every source in dependency order, then recursively audits all declarations, allowing only `propext`, `Classical.choice` and `Quot.sound`. It uses neither `sorry` nor native evaluation. The full finite enumeration is deliberately expensive. `bash replay.sh --audit-only` audits already built artifacts and does not claim a fresh source rebuild.

For this checkpoint, the 69 new modules were freshly rebuilt inside this snapshot with kernel checking. Earlier producer packets were separately checked. The full 951-module snapshot was hash/import-checked and recursively audited using those artifacts. The separate hosted `Progress Lean cohorts` workflow now builds the entire dependency-closed snapshot in four cohorts, selectively reusing exact-source verified project artifacts, then runs the complete combined audit. Its manual clean mode bypasses project cache reuse; see [the CI design](../../../../docs/PROGRESS_CI.md). The local checkpoint result does not claim that the hosted run has completed. The exact combined result and repository-check results are recorded in `checkpoint-verification.json`; it distinguishes that combined audit from a fresh rebuild of every snapshot module. Compiler binaries and the pinned Mathlib cache are trusted inputs. Needed upstream Mathlib files missing from that cache are compiled from their original pinned sources. The identity-cotangent and universal-sheaf-differential modules use canonical imports instead of duplicated upstream declarations; their producer proof bodies are unchanged, and the import-only adjustments are recorded with both source hashes.
