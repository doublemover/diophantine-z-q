# Native source-binder / elaborated-type comparison design

Status: design grounded in Lean v4.35.0 primary source. No comparator has been implemented or run. No local Lean execution. Existing lexical candidates remain advisory; hosted signature probes are the first actual elaboration evidence.

## What the compiler actually does

`Lean/Parser/Command.lean:397-415` documents that proof-body usage does not select theorem section parameters. `Lean/Elab/MutualDef.lean:444-490` implements the selection in private `withHeaderSecVars`: collect free variables of elaborated headers, explicitly included section variables, their transitive dependencies, and eligible instance-implicit SECTION variables. A `local instance` declaration is not interchangeable with a section `[Fact p]` binder. Header type elaboration can itself introduce dependencies absent from printed source, including a scalar-action instance applied to a proof parameter. The actual expression, not identifier spelling, must decide this.

`MutualDef.lean:534` applies selection before the proof body. `MutualDef.lean:1278-1293` constructs an asynchronous theorem's committed type from the selected header before checking its body. Consequently a printed signature in a failed module is NOT an accepted theorem. Signature, successful body/kernel checking, and source-to-type agreement must be separate result fields.

## Minimal implementation stages, in order

1. **Native signature extraction, read-only.** After a successfully checked module, resolve each fully qualified declaration, obtain `ConstantInfo.type`, traverse its actual `Expr.forallE` telescope without unfolding away proof-parameter dependencies. Record binder index, binder info, domain expression with de Bruijn dependencies and universe parameters, and constant dependencies. A pretty-printed type is a display field, never the comparison representation. Refuse acceptance if the declaration or dependency contains synthetic `sorryAx`, compilation failed, or its requested module was not checked. Missing declarations are UNKNOWN/BLOCKED, not premise-free. `ConstantInfo.type` alone has no authoritative successful-body/error-status bit: bind it to module exit status and elaboration diagnostics, inspect theorem values/dependencies for `sorryAx`, and distinguish genuine source axioms from a theorem header provisionally exposed by asynchronous elaboration. An axiom-free-looking header is insufficient if its body task failed or is incomplete.
2. **Native syntax inventory.** Record actual parser `Syntax` for the command, not a regexp approximation. Use `Parser.Command.declaration`, the particular declaration kind and `declSig`; retain binder Syntax and source spans. Distinguish explicit/implicit/strict-implicit/instance binders, including grouped identifiers, anonymous instances, macro-expanded commands, namespace qualification, and auto-bound identifiers. `Command.getBracketedBinderIds` is public; `Term.toBinderViews` is private, so do not call it from an external plugin. Public `Term.elabBindersEx` supplies Syntax/Expr pairs, and `Command.runTermElabM` elaborates active scoped variables with their unique IDs. Prefer observing existing elaboration over independently elaborating a header a second time.
3. **Semantic identity bridge.** Use `TermInfo.isBinder`, `TermInfo.stx`, `TermInfo.expr` and its saved `lctx`/metavariable context to map source spans to actual `FVarId`s. The compiler explicitly re-adds binder info for proof-body fvars at `MutualDef.lean:536-540`; a single source binder can therefore have multiple elaboration-local identities. Track source span plus context, not raw FVarId globally. `ContextInfo.parentDecl?` identifies the enclosing declaration; `CommandContextInfo.cmdEnv?` provides its final environment. Do not compare names alone: local renaming, shadowing, anonymous instance generation and hygienic macros make that unsound.
4. **Selection explanation.** Record active section binders, include/omit scope and actual elaborated header free-variable closure. Explain each retained binder as written-declaration, direct-header, transitive-domain, explicitly-included, eligible-section-instance or auto-bound. The current selection routine is PRIVATE; a plugin must either observe its results through info trees or maintain a clearly version-pinned reproduction tested against controls. It cannot pretend that all active source variables were intended theorem premises. Use `DefViewElabHeader.numParams`/binder info and `PreDefinition.numSectionVars` only with a version-specific instrumentation hook, not assumed public external metadata.
5. **Comparison and consumer validation.** Alpha-normalize corresponding telescopes by identity/dependency and compare `BinderInfo` and domain types in a shared local context (using definitional equality only after explicit corresponding dependencies are introduced). Report PRESENT_EXPLICIT, PRESENT_IMPLICIT, PRESENT_INSTANCE, ABSENT_ALLOWED, UNRESOLVED_PROVENANCE or ELABORATION_FAILED. A source-mentioned proof token missing from the actual telescope is not automatically a hidden assumption. For consumers, inspect the elaborated application spine and argument positions, then pair source syntax with argument provenance: explicit written argument, inferred implicit argument, synthesized instance, or still-free theorem parameter. Do not conclude that a parameter is discharged just because it is not written at the call site.

## Generic-field application

The original source has section `(b : Fin 4 → ℂ) (hb : Function.Injective b)`. All six family consumers write `hb` explicitly. `actual_field` and `actual_degree` bodies obtain a `Fact` through local instance synthesis; this is not evidence by itself that their theorem headers retain `hb`. The four direct-include diagnostic variant deliberately holds these two indirect cases unchanged. If that variant fails at instance synthesis, record that exact failure before introducing a further bounded repair. The original specialization constructs `branches_injective` from actual labeled points. Four numerical j equalities are separate explicit hypotheses downstream and are not solved by generic degree16, native degree8 or a successful binder diagnostic.

The existing separate `GenericBinderAudit318` import cannot print signatures if GenericField itself fails. A subsequent hosted-only diagnostic may append the six `#check @...` commands to a temporary exact-hash-tagged producer copy, capturing provisional signatures plus error diagnostics in the same process. Such output must be marked FAILED_ELABORATION, never theorem admission. Keep original and modified sources separately hashed; do not silently alter the frozen producer.

## Required control outcomes

Run explicit binders, source header dependencies, section typeclasses, local instance declarations, dependent definitions, renaming/shadowing, include, omit and deliberate proof-only failure controls. Add a dependent scalar-action test matching Module.finrank and a macro-generated declaration test before promoting a general comparator. Preserve errors, timeouts, stdout and exact source/toolchain hashes separately. A control that fails unexpectedly invalidates that comparator coverage, not the mathematical theorem. No automated source/type comparator is currently claimed.
