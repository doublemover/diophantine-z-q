# Independent bounded review: isolated experimental Lean checker

Decision: accepted for first-check isolation and accurately limited reporting, for the exact sources bound in BINDINGS.json. No current cache reuse or unintended scope-promotion defect was found. This is a non-author review of the checker, not acceptance of the eight mathematical drafts.

The experiment admission code verifies each source hash and declared import set, requires preceding packet imports or named baseline/official imports, and excludes baseline names, official root module names, and the two reserved audit names. The requested official-root shadowing hardening is present. Twelve independently constructed official/reserved-name negative controls were rejected. The repository's nine lightweight Python regression tests passed; no Lean compilation was performed in this review.

Baseline reuse requires a PASS receipt with the full recursive-audit scope and exact baseline base key. For each dependency-closed required module, ci.reusable checks its recursive source key, the exact dependency artifact hash lists, and its own artifact bytes; copy_artifacts rechecks bytes. A different overall baseline snapshot is permissible because the reused recursive closure is checked individually. This is trusted CI artifact reuse, not a claim that artifact hashes independently certify Lean proofs. Pinned official artifacts retain the accepted workflow's existing trust model.

The output directory must be fresh. Only validated required baseline artifacts enter its lib directory; LEAN_PATH is replaced with that lib and the pinned dependency libraries, and inherited LEAN_SRC_PATH is removed. Draft module names cannot replace any accepted baseline or official root. Each draft uses the accepted strict compiler flags and a 180-second workflow limit. Timeout returns failure. The audit imports all each new module, enumerates all its module declarations (including private/generated declarations), recursively collects axioms, permits only propext, Quot.sound and Classical.choice, and checks that every new module was found.

The workflow has read-only repository permissions, restores but never saves the full baseline cache, and uploads only RESULT.json, audit source and logs. It neither uploads draft .olean files nor changes the accepted progress manifest. PASS is expressly scoped to individual strict checks and a packet audit, with new_source_acceptance and full_arithmetic_theorem_proved both false. The source/axiom lint is defense in depth, not an asserted sandbox for adversarial Lean metaprograms.

Both real packets pass source/intake validation: six modules require 197 baseline modules, two modules require 188. Their upstream target output contains only module names and excludes every Lean/Std/Init prefix. The targets command omits manifest chatter while derive_plan still checks source hashes and accepted ordering.

Boundaries: this review does not claim the drafts compile, that their mathematical statements are independently accepted, that a full baseline replay occurred, or that a global analytic/arithmetic/PEL comparison has been proved. The tests are lightweight admission and failure controls. The reviewer authored the mathematical drafts but did not author the checker or workflow.
