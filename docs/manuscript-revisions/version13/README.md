## Installation

The author package is under `work/quartic-v13-prep/inventory`. Copy the contents of its `payload` directory into the repository root, preserving relative paths. This installs only the Version13 documentation subtree. The parent task separately installs agent10's complete package at `quartics/quartic-394-411`. Keep the existing `manuscripts/quartic_v11.tex`, `manuscripts/quartic_v12.tex`, Version12 addition and `docs/theorem-application-audit/sources.json` unchanged.

Run from the repository root:

    python -B docs/manuscript-revisions/version13/validate-applications.py --repo . --self-test --report inventory-validation.json

The validator has no third-party dependencies and no reference to the author's absolute filesystem paths. The author-side `staging` directory is a self-contained test fixture, not an installation overlay. The untouched draft, map and row inventory are preserved separately in `author-originals`. `build.py`, `specs.py` and `PATH-MAP.json` document the transformation; they are author tools, not runtime dependencies of the portable validator.

Do not copy a historical approval to this inventory or update current.json/contracts merely to match its hash. The root task must bind and independently review the exact full manuscript and application contract under the repository protocol. This package does not edit those files.

## What the checks establish

Validation passes for39 applications,351 obligations, seven component transports,97 changed rows,47 compatibility labels,629 file-pin occurrences,212 source/consumer spans and155 label bindings. It checks complete old/new coordinate incidence and unchanged rows, exact external-source metadata, inherited record hashes, new-label uniqueness and cross-references. Ten negative controls were rejected: missing application, missing obligation, missing one of multiple consumers, stale source pin, absolute path, changed external version, omitted new obligation, invented acceptance, missing source file and changed source bytes. The two filesystem controls operate on a temporary relocated copy and never modify supplied sources.

The operative inventory, map, component records and verifier use repository-relative paths. Research evidence is supplied under `evidence` with content-addressed names. The external copyrighted source texts are not asserted to be redistributed; their exact version and byte metadata are verified against the inherited public catalog. This is structural provenance and coverage validation, not a mathematical acceptance verdict.
